temporary `.best_model.pt.*` file disappeared between listing and `stat()`.

## Scientific and output contracts

### Split, label, and transform contracts

- Missing task labels use sentinel `-1` and are masked task-by-task.
- Rare classes are masked per task by unique-individual count.
- Split generation is stratified at individual/group level with test seed
  `seed` and validation seed `seed + 1`.
- Predefined CSV loading is a separate path and currently enabled by default.
- Ordinary multi-task training uses resize, training-only horizontal/vertical
  flips and 270-degree random rotation, tensor conversion, colour retention,
  then ImageNet normalisation.
- Matched-condition training applies the same deterministic cue manipulation
  to train, validation, and test; only training receives geometric augmentation.
- Fixed-RGB stress testing builds deterministic `train=False` transforms and
  evaluates the already selected checkpoint. It must never become training.

### Sweep contract and nested-expansion prevention

`generate_dual_cue_run_specs.py` expands ordinary sweep combinations and
unique matched conditions once. Every generated spec appends:

```text
matched_condition_training.enabled=false
```

and the SLURM array invocation appends:

```text
sweep.enabled=false
```

Thus one array task maps to one training configuration. Original RGB is an
alias of saturation retention 1.0; grayscale is an alias of retention 0.0.
Endpoint deduplication prevents redundant model training.

### Checkpoint schemas

Ordinary/hierarchy checkpoints contain exactly:

```text

```

Colour-ablation adds `colour_retention` and `colour_percent`. Cue-suppression
adds those keys plus `training_condition`. Notebook loaders depend on these
keys and on `best_model.pt`.

### Metric and W&B contracts

Epoch/test metric dictionaries use:

```text
loss
hierarchy_loss                         # hierarchy-enabled workflows
<task>_loss
<task>_n
<task>_accuracy
<task>_balanced_accuracy
<task>_macro_f1
mean_macro_f1
complete_exact_match_accuracy
complete_exact_match_n
```

History prefixes these with `train_` and `val_`. W&B prefixes numeric metrics
with `train/`, `val/`, and `test/`, and defines `epoch`, `train/*`, `val/*`, and
`learning_rate`. Summary keys include best epoch/score/selection metric and,
for cue workflows, colour and training-condition metadata. Environment
fallbacks are `WANDB_PROJECT`, `WANDB_ENTITY`, `WANDB_NAME`,
`WANDB_RUN_GROUP`, and `WANDB_MODE`. Model artifacts are named
`<run_name>-best-model` when enabled.

## Risks, ambiguities, and dynamic paths

1. Active jobs mutate `outputs_slurm`, so result-tree inventory is inherently
   time-dependent. Source validation must exclude those trees.
2. The working tree was already dirty and includes behaviour-affecting shared
   module edits. Baseline snapshots must state whether they target the commit or
   current working tree.
3. `cam_mutlitask.ipynb` is empty. This is a pre-existing failure and will not
   be repaired or deleted without instruction.
4. Notebook roots are selected through `Path.cwd()`, absolute external paths,
   and dynamic globbing. Static extraction cannot identify every chosen run.
5. Shell paths depend on two clusters, accounts, partitions, Conda locations,
   node names, `$TMPDIR`, `/scratch`, symlink resolution, and external datasets.
6. Generated SLURM scripts are tracked in `outputs_slurm`; they may reflect
   historical behaviour but should not be edited.
7. `config_old.yaml` contains legacy dotted override spelling that does not
   match current runtime reads. It is documented, not fixed.
8. The environment lacks a complete declared dependency lock and HPC/GPU tests
   are not available locally.
9. Several functions with identical names are not necessarily equivalent;
   colour/cue/hierarchy variants require differential fixtures before sharing.
10. Existing notebooks and external users may import functions not detected by
    static search. Old modules and paths must remain available.
